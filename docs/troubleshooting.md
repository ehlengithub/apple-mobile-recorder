# 更新后提示后台版本不兼容

工作台现在核对导入时的源码指纹、API 能力和代码/数据目录。更新源码后，先退出原工作台进程，再重新启动；不要只刷新旧后台的页面。启动器不会自动杀掉无关服务。源码与后台不匹配时拒绝新操作，保留停止入口。

蓝牙启用或切电脑录制回应丢失时，命令可能已经执行；以“已核验软件停止”或“可能已运行”的实际提示为准。保持供电长按 BOOT 两秒进入持久维护后重新核验，不盲目重试启用。详见[七项修复说明](review-fixes.md)。

# 先按控制方式排障

**蓝牙整合版先看[蓝牙流程](bluetooth.md)。** 上传前保持供电长按BOOT两秒，进入持久维护并断开连接；启用前放好目标起始页。选错控制器、MAC、未持久维护、BLE仍连接，后台都会拒绝操作。USB沿用拔HID后管理。

新BLE固件默认不广播，先用工作台在维护状态下切电脑录制（需Wi-Fi配置），或上传后明确启用。找不到名字不能直接判定坏板。旧固件无AMR2上传能力，需要首次安装共用播放器。

iPad已配对但不点击：连接、加密、输入报告订阅缺一不可；桌面录制还要确认真实投屏有新帧且control_transport=ble。报告描述符保持旧版，必要时再忽略旧配对并重配。独立供电后的串口缓存不代表实时连接状态。

以下旧段落主要记录USB/v1历史；新版以README与bluetooth.md为准。

# 排障：投屏、点击与离线循环

核对日期：**2026-10-30**。以下端口和停止方式针对本项目当前 ESP32-S3 板卡/固件。真实页面验收仅限iPad14,3；当前首步 3 秒六步版仅编译、烧录、板端自检，尚无页面验收。完整边界见[兼容性文档](compatibility.md)。

## 1. 先停止，再检查

离线运行时：

1. 按住板上 **BOOT** 约半秒。
2. 确认实体 iPad 已停止点击。

若仍在点击，直接拔掉 **USB/HID** 线。BOOT 松手不会继续；重新开始需回到起始页面后重新插拔 HID。

**不要用 EN/RESET 当停止键**：部署锁解除后，正常上电或硬件复位会重新启动循环。不要按住 BOOT 再复位，以免进入下载模式。网页 Esc/急停仅作用于电脑端 AI/宏回放，不能停止板内离线循环；关闭网页、停止投屏也不能停止离线固件。

## 2. 板子亮灯，但 iPad 没有指针或点击

| 端口 | 正确连接 | 作用 |
| --- | --- | --- |
| COM | Mac；独立使用时可作外部供电入口 | 串口诊断/烧录与供电，不向 iPad 发送鼠标输入 |
| USB/HID | 被控 iPad | 原生 USB HID 绝对鼠标输入 |

1. 核对板上 COM 与 USB/HID 标识。
2. 将 USB/HID 接到被控 iPad。
3. 解锁 iPad。
4. 确认设备上的配件批准提示。
5. 开启“设置 → 辅助功能 → 触控 → 辅助触控”。
6. 更换已知可传数据的线材复查。

官方依据：有线鼠标可经 Lightning/USB-C 接入，USB-A 设备需转换器；默认需解锁才能连接配件，仍不识别时应在解锁后重连。[指针设备](https://support.apple.com/zh-cn/111775)、[辅助触控开关](https://support.apple.com/zh-cn/111794)、[配件连接与解锁](https://support.apple.com/zh-cn/111806)（均检索于 2026-10-30）。

充电灯亮仅说明有供电，不证明 USB 数据/HID 枚举成功。USB-C 直连仍取决于板卡、线材、主机识别和供电；Lightning 方案未完成本项目硬件验收，不能承诺换一个转接头即能解决。

## 3. 提示配件耗电过多，或连接反复断开

1. 停止离线循环。
2. 核对线材及转接器连接。
3. 按板卡既有供电方式，通过 COM 补充供电。
4. 解锁设备后重新连接 HID。

苹果说明某些 USB 配件可能超过设备供电能力，并列出带电源集线器或闪电转 USB 3 相机转换器的供电方法。[官方供电说明（英文）](https://support.apple.com/en-ie/111811)（检索：2026-10-30）。这是排查方向，不能保证某个 Lightning 转接器与当前 ESP32-S3 兼容；COM 补电也不能修复错误的数据连接或未支持的硬件组合。

## 4. 首次烧录后一直待机，断电也不开始

这是首次部署的持久待机锁。**断电或 EN 复位不会解除首次部署锁**；板子必须在持续供电时看到一次 HID 从已连接变为断开。

1. 保持 COM 接 Mac 供电。
2. 将 USB/HID 接上已解锁的 iPad，等待连接就绪。
3. 将 iPad 放到录制起始页面。
4. 仅拔掉 USB/HID 线。
5. 重新插入 USB/HID 线。
6. 等待 USB 就绪后的 10 秒启动倒计时与首步间隔。

当前首步 3 秒版首次按压约在就绪后 **13.35 秒**，不是插线即点。之后若保持稳定供电，可独立循环；每次新部署仍须重新解除部署锁。USB 休眠或发送失败会停止，恢复亮屏不会续跑半轮，应回到起始页后重新插拔 HID。

## 5. 打开 COM 后突然重启或重新点击

本板打开 COM 可能触发硬件复位。部署锁已解除时，这可能重新启动倒计时；串口连接不是无干扰监视器。

1. 先用 BOOT 停止，或拔掉 HID。
2. 再打开串口诊断工具。

不要为了查看状态，在未准备好的真实页面上反复打开 COM。板端 `dryrun` 不发送 HID 报告；自检成功、日志完整均不等于真实点击命中。

## 6. 电脑画面正常，但点到了另一台设备

AirPlay 画面与 HID 输入是两条独立链路，不能假定设备名称或连接状态已自动绑定二者。

1. 停止回放。
2. 核对 HID 线实际接入的设备。
3. 在该设备上手动切换一个无风险页面。
4. 确认电脑画面同步变化。
5. 回到原起始页后再录制。

看见其他设备或其他接收器的镜像时，不要继续点击。

## 7. 投屏找不到、断流，或网页拒绝点击

1. 先停止电脑端宏回放。
2. 将被控设备与电脑接入同一 Wi-Fi。
3. 解锁被控设备。
4. 在“控制中心 → 屏幕镜像”选择本项目实际接收器。
5. 如出现 AirPlay 密码，在被控设备上输入。
6. 手动切换页面，确认电脑画面持续更新。

同一 Wi-Fi、选择接收器和输入密码来自[苹果镜像操作说明](https://support.apple.com/zh-cn/102661)；可继续参考[苹果 AirPlay 排障](https://support.apple.com/zh-cn/102587)（均检索于 2026-10-30）。若使用苹果内建接收器，另查 [Mac 接收权限和系统要求](https://support.apple.com/zh-cn/guide/mac-help/mchld7e543a0/mac)（检索：2026-10-30）。本项目 UxPlay 的状态仍须单独检查，苹果内建接收器可用不等于 UxPlay 已收到画面。

电脑端在识别到直播不可用、画面过期或无法确认指针位置时会拒绝绝对坐标点击，应先恢复画面，不要绕过检查。旧截图、进程存在或网页打开成功，都不能证明直播正常；检测也不能保证中断瞬间立即判定。**这一保护不适用于板内离线循环。**

## 8. 投屏只显示第一帧：检查 `videorate` 与 PTS

项目源码记录的原因：UxPlay 使用 `-vsync no` 时，解码帧缺少 PTS（显示时间戳）；下游加入 `videorate` 会丢弃首帧后的帧。

1. 停止点击和回放。
2. 请维护者核对实际使用的接收管线与 `server/hidagent/screen.py`。
3. 确认使用当前实现的 `-fps` 控制源帧率，未额外插入 `videorate`。
4. 修正接收管线并恢复投屏后，切换页面验证连续更新。

当前源码采用 `queue … leaky=downstream → jpegenc → sink`。若实际启动了旧副本或旧接收器，只刷新网页不会修复。此项依据本项目源码，不是苹果官方兼容性结论。

## 9. 越点越偏、换设备后坐标不准

相对鼠标依赖位移累计，可能受加速度、边界和校准误差影响而漂移。本项目正式路线为 USB 绝对定位；电脑端状态应为 `pointer_mode: absolute`。绝对定位仍不保证弹窗、按钮吸附、布局变化或错误页面上的点击正确。

1. 停止回放。
2. 核对当前固件及电脑端指针模式。
3. 恢复录制时的设备方向、缩放与起始页。
4. 更换设备或布局后，重新录制坐标。
5. 逐步观察实际页面命中再启用循环。

不要通过反复补偿相对位移来沿用当前绝对坐标录制；也不要把一台 iPad 的坐标直接用于另一台 iPad 或 iPhone。刷入离线固件后，网页显示设备离线可能是预期行为；若要恢复电脑控制，需由维护者恢复对应的电脑控制固件。

## 10. 离线循环漏选、遇到弹窗或列表到底仍继续

离线板端仅保存坐标和时序，没有图像或页面状态识别能力，不能识别弹窗、列表到底、提交失败或页面切换失败，也不能自动决定何时停止。

1. 按 BOOT 停止。
2. 手动关闭弹窗或恢复起始页。
3. 核对实际页面响应是否慢于录制间隔。
4. 需要时由维护者增加等待并重新部署。
5. 观察真实页面完成逐步及跨轮验收。

当前间隔为 `3, 0.5, 0.5, 0.5, 0.5, 2.588` 秒，定位稳定 350ms、按压 60ms、释放后至少等 90ms。此前首步 1.435 秒版的用户确认，不能替代当前首步 3 秒版页面验收；本版仍标记为**仅编译/烧录/板端自检**。

## 11. 是否需要安装配套 App 或 Apple 签名

当前方案不要求在 iPhone/iPad 安装配套 App，不需要 Apple 开发者账户或应用签名。先排查辅助触控、解锁、HID 数据链路及 AirPlay；不要把安装上游可选 App 当作必要修复步骤。项目基于 [ESP32 iPhone Agent](https://github.com/onehumanbeing/esp32-iphone-agent)，作者 Henry Yuan；对外演示请注明来源。

## 通用播放器 v2：上传录制和模式切换

以下流程取代上文旧版“每换录制重刷一次”和“首次重插解部署锁”的步骤：

1. 首次安装通用播放器；需要电脑录制时在构建前填写Wi-Fi与电脑地址。
2. COM接电脑，USB/HID从移动设备拔下，核对板卡MAC。
3. 上传录制，等待上传与逐字节读回成功。
4. 明确点“启用：下次插入执行”，再将USB/HID接回起始页设备。

- 一直待机：确认已经上传并启用。只有上传成功不会自行执行。
- 提示 `hid-connected`：拔下USB/HID后重试；不要绕过检测。
- 提示 `desktop-unavailable-no-secrets`：首次播放器没有配置电脑录制网络，需安装含配置的播放器一次；以后换录制无需重刷。
- 上传中断：旧录制保留但自动执行被关闭；重新上传、确认读回、明确启用。不要把失败后仍有旧录制理解成已更新。
- 刷新网页：从任务历史选择原烧录任务恢复；备份缺失或当前分区变化会拒绝。
- 恢复固件不恢复录制：应用备份不含NVS录制数据，优先从本机原项目重新上传；上传任务也保留旧录制数据备份。
- 电脑试跑：已修复新工作台就绪时的 `no running event loop` 调度错误；其他图像或连接校验仍生效。

本轮v2仍需首次实板上传和一轮页面验收；旧iPad固件的成功不能代替v2验收。
