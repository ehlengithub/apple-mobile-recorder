# Apple Mobile Recorder

**在电脑上操作 iPhone / iPad，录下点击，改好每步间隔，上传到 ESP32-S3。通用播放器只需安装一次，以后改录制不用重新烧录。**

基于 [ESP32 iPhone Agent](https://github.com/onehumanbeing/esp32-iphone-agent) by **Henry Yuan**，保留原 [MIT LICENSE](LICENSE) 和 [NOTICE](NOTICE)。对外演示、视频和文章也请注明原项目来源。

本项目把原来分散的命令整理为一个中文工作台：**首次安装播放器 → 设备档案 → 录制 → 时间表 → 试跑 → 上传录制 → 启用离线执行**。录制和离线点击都不需要模型 API Key，也不用在手机上安装配套 App、开启开发者模式或处理签名有效期。

[初版工作台截图](docs/workbench.png) · [兼容性](docs/compatibility.md) · [排障](docs/troubleshooting.md) · [验证记录](docs/validation.md)

## 先看适用范围

| 项目 | 当前范围 |
| --- | --- |
| 电脑 | macOS / Apple Silicon 完成本次工作台验证；Windows、Linux 未做端到端验收 |
| 板卡 | 双口 ESP32-S3：COM 用于首次安装及后续录制上传，原生 USB/HID 接被控设备；参考构建为 ESP32 Arduino 3.3.12、8MB Flash 配置 |
| 被控设备 | 按 iPhone / iPad、接口、画面尺寸和横竖屏分别建档。核心 USB 绝对定位在 iPad14,3 验收过；其他机型需单独验收 |
| 离线动作 | **点击**，最多256步；支持每步间隔、启动倒计时、指定轮数或无限循环 |
| 电脑试跑 | 保留目标局部画面和实际指针检查，页面不符会暂停 |
| 离线限制 | 无画面输入，不能识别弹窗、列表到底或页面变化；坐标相同不代表页面始终正确 |

Lightning 机型需要适用的转接与供电方案，本项目没有实测该组合。**不能因为苹果支持鼠标，就宣称本项目所有 iPhone / iPad 均已适配。** 接线和官方依据见 [兼容性说明](docs/compatibility.md)。

## 你日常只需要这条流程

### 第一次准备电脑

已安装 Homebrew 的 Mac，运行一次：

```sh
bash scripts/setup-macos.sh
```

随后双击 **[启动工作台.command](启动工作台.command)**，浏览器打开 `http://127.0.0.1:8990/`，AirPlay 接收器名为 **Apple Recorder**。首次安装会准备 Python、UxPlay、Arduino 工具及固定版本的板卡支持包，**不会自行烧录设备**。

### 首次安装播放器（只做一次）

1. 展开“播放器的电脑录制连接配置”，填写 Wi-Fi、电脑局域网 IP 和控制端口。
2. 生成**支持电脑录制的通用播放器**。
3. 拔下连接手机/iPad的 USB/HID，COM 接电脑，选择正确端口，点“备份后烧录”。只有真实空板才勾选初始化。
4. 在“上传录制”区域核对板卡 MAC，勾选 USB/HID 已断开，点“切回电脑录制”。

播放器默认没有录制，不会开机盲点。未配置 Wi-Fi 的播放器只能离线执行；后续首次补充或修改网络配置仍需重新安装一次固件。**修改点击、间隔、设备档案或循环次数不需要重刷。**

### 录一套新操作

1. 保持 COM 接电脑、USB/HID 暂时断开，点“切回电脑录制”。
2. 将 USB/HID 接目标设备，解锁并开启辅助触控。
3. 在该设备“控制中心 → 屏幕镜像”选择 **Apple Recorder**。
4. 在工作台选择设备类型、接口与方向，确认尺寸和被控设备一致。
5. 点“开始录制”，在电脑画面完成点击，完成后保存刚才的录制。

录制使用 USB **绝对定位**；电脑端点击保留指针与局部画面校验。板内离线执行没有这些画面检查。换设备或方向后重新录制，不能把同一套坐标直接套用所有屏幕。

### 改时间、上传，不再重新烧录

1. 修改时间表，首次将循环次数设为 **1**，保存并在起始页做“电脑试跑1轮”。
2. 拔下 USB/HID，COM 继续接电脑，核对 COM 口与 MAC，勾选已断开。
3. 点“保存并上传录制”；上传完成会逐字节读回校验，并保持待机。
4. 点“启用：下次插入执行”。
5. 把目标设备放回起始页，再插 USB/HID，等待倒计时并观察一轮。
6. 确认正确后可将循环次数设为 **0**，按同样步骤重新上传和启用。

**上传和启用分开，上传本身不会启动循环。** 数据有版本、长度、步骤/时序检查与 CRC32；板端使用双槽并在读回校验后原子切换。上传中断保留旧录制，写入前先持久关闭自动执行；不要把中断当成功，重新上传并确认后再启用。

### 脱离电脑使用

启用后回到录制起始页，连接 USB/HID，等待设定倒计时。设备供电足够时可不接 COM；不需要 Wi-Fi 或电脑。按实体 **BOOT** 停止，松开不会续跑；重插 USB/HID 或普通重新上电可能再次启动。网页 Esc 只停止电脑回放，EN/RESET 不是停止键。

打开 COM 可能触发复位；上传、启用、切模式均要求先拔下 USB/HID，固件也会拒绝连接目标设备时修改。换成旧固件不支持录制上传，须先安装通用播放器一次。

## 每步间隔的准确含义

间隔按**上一步开始定位 → 本步开始定位**计时，已经包含定位稳定和按压，不是点击后再额外加一遍等待。

默认固定保留 **350ms 定位稳定 + 60ms 按压**，释放后至少90ms，因此最短间隔为 **500ms**。项目校验会拒绝更短的值，不会表面写0.5秒、实际却被旧的1秒下限拖慢。

现有 iPad 六步示例的间隔为：

| 步骤 | 执行前间隔 |
| --- | ---: |
| 1 | 3秒，接上一轮第6步 |
| 2～5 | 各0.5秒 |
| 6 | 2.588秒 |
| 合计 | 7.588秒/轮，不含首次倒计时 |

[现有 iPad 示例](examples/ipad-six-step.json) 仅适用于原设备和原页面布局，不能直接拿去操作另一台 iPhone。[iPhone 示例](examples/iphone-nine-point.json) 展示通用项目格式，使用前应在对应设备重新录制。新设备建议先在 [九点测试页](examples/targets/index.html) 验收，避免拿真实业务试错。

## 一份固件，两种运行模式

| | 电脑录制模式 | 离线执行模式 |
| --- | --- | --- |
| 电脑 / Wi-Fi | 需要首次安装时配置 | 执行时不需要 |
| 画面校验 | 电脑保留 | 没有 |
| 停止方式 | 网页停止 / BOOT | BOOT / 拔 USB/HID |
| 换录制 | 电脑录下并保存 | 上传独立 `.amr` 文件，不重刷固件 |
| 切换模式 | USB/HID断开时点“切回电脑录制” | 上传后明确启用 |

多个设备的录制分开保存。板子不会自动识别插入的设备身份；选错录制仍可能点错页面。

## 备份、恢复与数据

- 默认数据在 `~/.apple-mobile-recorder/studio/`，只有当前用户可访问。项目 JSON 不含画面；电脑试跑的原图校验依据仅在本机保存。
- 每次烧录先读取板型、启动区、分区表和应用区。分区不兼容、备份失败或固件 SHA256 改变时不写入；备份步骤之间保持下载模式，避免误启动旧循环。
- 默认只写应用区 `0x10000`。明确勾选空板初始化且启动区确实为空时，才写对应启动文件和分区表。
- 烧录后可点“恢复烧录前版本”，或按 [CLI 说明](docs/architecture.md) 指定原烧录任务恢复。恢复时核对原板卡 MAC、备份哈希和板上当前分区；同板被其他工具重新分区后也会拒绝直接恢复。任务与备份历史在刷新或重开网页后仍可选择。
- 录制上传前会把旧录制读回保存到本机任务目录 `previous.amr`；固件备份和录制备份用途不同。
- 备份是应用/启动区快照，**不是完整 Flash / NVS 克隆**。录制模式二进制可能含 Wi-Fi 连接配置，不能上传到公开仓库。
- 串口115200模式优先稳定；读取应用备份可能需要数分钟。这段耗时不代表卡死。不要在烧录写入时拔线。

## 已验证与待验证

原核心在 iPad14,3 上完成绝对定位、循环和无 COM 运行验证；六步半秒版首步1.435秒也经用户确认正常。首步加长到3秒的原板端版本只有烧录和板端自检记录，尚无该版页面验收。

v2已通过206项Python、14项Node UI、C++故障/变异测试与两种真实Arduino编译；没有实板部署，仍需先做测试页验收。

本仓库增加的通用工作台另行测试：参数编辑/恢复、生成链路、项目校验、备份失败拦截、独立构建及有限轮数。**浏览器测试、编译成功、板端自检、真实页面成功是不同证据。** 详细记录见 [验证记录](docs/validation.md)。

## 少走弯路

遇到问题先看 [排障](docs/troubleshooting.md)：端口接反、画面与被控设备不一致、相对鼠标漂移、AirPlay首帧后不更新、播放器未启用、打开 COM 触发复位、离线无法识别弹窗等，均有对应检查路径。

开发、命令行、构建目录和接口说明见 [架构与CLI](docs/architecture.md)。本机改动保留了 [UxPlay 来源和补丁说明](integrations/uxplay/README.md)；UxPlay 单独遵循其 GPL 许可，不并入本项目 MIT 许可。
