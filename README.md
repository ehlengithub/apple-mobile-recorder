# Apple Mobile Recorder

**在电脑上录制 iPhone / iPad 点击，调整间隔，上传到 ESP32。支持蓝牙和 USB；播放器只需安装一次，以后改录制不用重新烧录。**

基于 [ESP32 iPhone Agent](https://github.com/onehumanbeing/esp32-iphone-agent) by **Henry Yuan**，保留原 [MIT LICENSE](LICENSE) 与 [NOTICE](NOTICE)。对外演示、视频和文章请注明原项目来源。

共用中文工作台、设备档案、时间表、`.amr` 录制、双槽存储与调度器；板端分 USB/BLE 驱动和构建。无需模型 API Key、手机配套 App、开发者模式或开发者签名。

[兼容性](docs/compatibility.md) · [蓝牙流程](docs/bluetooth.md) · [架构/CLI](docs/architecture.md) · [排障](docs/troubleshooting.md) · [验证记录](docs/validation.md)

## 两种控制方式

| | 蓝牙 | USB |
| --- | --- | --- |
| 工作台控制器 | 经典 ESP32 / 蓝牙 | ESP32-S3 / USB |
| 当前硬件 | ESP32-D0WDQ6，4MB Flash | 双口 ESP32-S3，参考8MB构建 |
| 连接手机/iPad | 蓝牙 HID 配对 | 原生 USB/HID 数据线 |
| 板子供电 | 普通电源/充电宝；管理时接电脑串口 | 目标设备或独立供电；管理时接COM |
| 更新录制前 | 保持供电，长按BOOT两秒进入持久维护模式 | 拔下连接移动设备的USB/HID |
| 启用后的行为 | 自动广播、连接已配对设备，倒计时后执行 | 下次插USB/HID，倒计时后执行 |
| 离线需要电脑/Wi-Fi | 不需要 | 不需要 |

**两种板子的固件不能互刷。** 工作台按控制器生成芯片/FQBN/启动地址，烧录时核对构建板型、芯片与分区；恢复使用备份记录的板型。串口号不等于芯片型号。

旧蓝牙版在iPad14,3已完成27/27九点测试、六步循环和独立供电恢复。**本轮接入通用播放器后的蓝牙版还须重新实板验收；旧版成功不等于新版已验收。** iPhone、其他机型及Lightning组合仍需分别验证。

## 第一次准备电脑

已安装Homebrew的Mac运行一次：

```sh
bash scripts/setup-macos.sh
```

脚本准备Python、UxPlay、Arduino ESP32 core **3.3.12** 与 NimBLE-Arduino **2.5.1**，不会自行烧录。随后双击 **[启动工作台.command](启动工作台.command)**，打开 `http://127.0.0.1:8990/`，AirPlay接收器为 **Apple Recorder**。

本轮以Apple Silicon Mac验证；Windows/Linux未做完整录制与实板部署验收。

## 首次安装播放器（只做一次）

1. 在工作台选择正确控制器：经典ESP32/蓝牙，或ESP32-S3/USB。
2. 展开首次电脑录制连接配置，填写Wi-Fi、电脑局域网IP与控制端口。
3. 生成支持电脑录制的通用播放器。
4. USB板先拔下USB/HID；旧蓝牙板先停止原循环并断开目标设备的蓝牙连接，再接电脑串口。
5. 选择串口，点“备份后烧录”。只有未初始化的真实空板才勾选初始化。
6. 在上传区域核对烧录任务识别的芯片MAC，确认当前控制器的管理条件，点“切回电脑录制”。

新蓝牙播放器默认持久维护，不广播输入；新USB播放器默认无录制。旧版自动执行设置不会迁成新版的运行许可。首次需要电脑录制，应安装含Wi-Fi配置的播放器；纯离线构建不带网络凭据。

修改Wi-Fi配置或升级播放器代码仍需重新安装固件；修改坐标、时间和循环次数只上传录制。

## 录一套新操作

1. 蓝牙板保持供电长按BOOT两秒；USB板拔下USB/HID。接电脑串口并确认维护条件。
2. 点“切回电脑录制”。蓝牙会恢复广播；USB可重新接回目标设备。
3. 蓝牙设备在iPad/iPhone配对 **iPad BLE Recorder**；解锁并开启辅助触控。
4. 在目标设备“控制中心 → 屏幕镜像”选择 **Apple Recorder**。
5. 选择手机/平板档案，核对方向、尺寸、投屏和被控设备一致。
6. 开始录制，在电脑实时画面点击，结束后保存录制。

电脑录制模式使用Wi-Fi把指令发到板子；板子用所选USB或蓝牙HID控制移动设备。离线模式关闭Wi-Fi。蓝牙保持已验收的鼠标描述符，目前不提供键盘输入；主工作台的点击录制可用，不会把不支持的动作静默丢弃。

## 改时间、上传，不再刷固件

1. 修改每步执行前间隔，首次将循环次数设为 **1**，保存并在起始页做电脑试跑。
2. 蓝牙板长按BOOT两秒进入维护；USB板拔下USB/HID。串口接电脑，核对板型、MAC并确认。
3. 点“保存并上传录制”，等待完整读回校验；完成后保持待机。
4. 将移动设备放回录制起始页。蓝牙板点“启用”后会自动连接并倒计时执行；USB板启用后再插回USB/HID。
5. 观察真实页面一轮，确认无漏选/点偏后，再改为 **0轮**、重新上传并启用持续循环。

**上传与启用分开。** AMR2数据严格校验版本、长度、CRC32、设备几何、坐标和时序；双槽写入后读回校验，最后原子切换活动槽。上传中断保留旧有效录制，写入前关闭自动执行；失败后重新上传并明确启用。启用前再次核对板内数据与当前项目逐字节相同。

打开COM/串口可能复位，不能把“插电脑”当成停止。蓝牙维护状态写入NVS，重启仍保持；后台会核对实际维护状态及是否已断开连接，单勾复选框不构成通过。控制器切换会清空MAC、维护确认与旧构建，防止沿用另一块板的状态。

## 离线执行与停止

启用后可脱离电脑、投屏和Wi-Fi。蓝牙板使用普通电源，自动连接已配对设备；USB板连接目标设备。运行时保持原起始页、方向和缩放。

**停止按实体BOOT，或断开板子供电。** USB也可拔HID。蓝牙更新前持续长按BOOT约两秒，进入持久维护并断开蓝牙；松手不会恢复。网页Esc只停止电脑回放，EN/RESET不是停止键。已启用状态下普通上电/重连可能从第一步重新倒计时；软件/异常复位保持待机。

离线没有画面输入，不能识别弹窗、列表到底、提交失败或按钮变化。绝对坐标减少位移累积漂移，不保证错误页面上的点击正确。

## 间隔和适用范围

间隔按“上一步开始定位 → 本步开始定位”计时，包含 **350ms定位稳定 + 60ms按压 + 至少90ms释放**，默认最短500ms。USB/BLE共用调度器；蓝牙通知提交成功不等于页面实际命中。

| 步骤 | 当前六步示例的执行前间隔 |
| --- | ---: |
| 1 | 3秒，接上一轮第6步 |
| 2～5 | 各0.5秒 |
| 6 | 2.588秒 |
| 合计 | 7.588秒/轮，不含首次倒计时 |

最多256步，当前离线只支持点击；支持启动倒计时、有限轮数和持续循环。设备档案与控制器分开：同一种录制格式可用于两种驱动，但更换设备、方向、缩放或布局后要重新录制/验收，不能自动跨机型适配。

[六步示例](examples/ipad-six-step.json)只适用于原布局；[iPhone示例](examples/iphone-nine-point.json)是格式示例，不是iPhone真机验收。初次迁移先用[九点测试页](examples/targets/index.html)。

## 备份、恢复与验证

- 默认私有数据在 `~/.apple-mobile-recorder/studio/`。项目JSON不含画面，电脑图像校验依据仅本机保存。
- 烧录前备份启动/分区区与应用；分区不兼容、备份失败或二进制变化时不写入。经典ESP32空板bootloader从`0x1000`写入，S3从`0x0`；普通升级只写应用`0x10000`。
- 任务历史在刷新/重开后仍可查询，恢复核对原芯片、MAC、快照哈希和当前分区。
- 固件备份不是完整NVS克隆，恢复固件不会回退板内录制；从本机原项目重新上传。上传前也会把旧录制存为任务目录的`previous.amr`。
- 原固件、完整Flash、录制、图像、日志和Wi-Fi凭据不提交Git。原厂完整备份仍保留在原部署目录，不能用另一块板的备份代替。
- [验证记录](docs/validation.md)区分旧版iPad实测、通用版本代码测试、真实编译与待完成的实板验收。
